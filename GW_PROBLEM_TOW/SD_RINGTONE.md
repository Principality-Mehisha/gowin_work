# SD 卡事件铃声与实时马林巴

当前版本已把 KEY0 目标切换为 `ANDROID.BIN`，播放三星 Over the Horizon 的马林巴声部演奏版；见 [ANDROID_RINGTONE.md](ANDROID_RINGTONE.md)。本文以下的苹果 `RINGTONE.BIN` 流程保留为历史说明，事件格式和播放控制仍适用。

2026-10-23。KEY0 的播放路径改为：

```text
KEY0 → SD SPI → FAT16/FAT32 → RINGTONE.BIN → M42S 校验
     → 事件 FIFO / 毫秒调度 → 实时马林巴 → PT8211
```

## 使用

- SD 卡根目录放 `RINGTONE.BIN`，保持 FAT16/FAT32。
- KEY0：开始读取并播放；加载或播放期间再按一次停止，清除合成尾音。停止后再按从头读取；播放结束自动回到手动模式。
- KEY1：默认 C2–F5 的 42 音逐音试听；铃声加载/播放期间忽略。
- KEY2：全局复位、停止铃声并回到 C2 试听。
- 读取、格式或计算错误时停止铃声，错误指示灯锁存；再按 KEY0 可重试，KEY2 清除错误。

原下载路径 `impl/pnr/GW_PROBLEM_TOW.fs` 已直接覆盖。SD 卡装回开发板后需要下载此版位流；修改 SD 文件不会改变旧版 FPGA 的 KEY0 行为。

## 指令格式

文件名为 ASCII 短文件名 `RINGTONE.BIN`，对应 FAT 8.3 字段 `RINGTONEBIN`。不用中文长文件名，以兼容当前根目录读取器。

M42S v1 复用原 P88S 的定长事件框架，但有不同的魔数和音高编号约定，避免钢琴乐谱被当成马林巴铃声：

| 部分 | 布局，小端序 |
| --- | --- |
| 16 字节头部 | `M42S`、版本 1、事件大小 8、槽位数 8、保留 0、时间基准 1000、事件数 |
| 8 字节事件 | 时间毫秒 u32、槽位 u8、MIDI 音高 u8、力度 u8、保留 0 |
| 力度 | 1–127 触发，0 松键；送合成器时乘 2 转为 Q0.8 |
| 允许音域 | MIDI 36–83，即 C2–B5 |
| 结束记录 | 槽位 255、音符 255、力度 0、保留 0 |

M42S 是格式标识，不是文件中的音符数量。事件必须时间非递减，文件长度必须严格等于头部声明；读取器检查格式、音域、结束记录和 EOF，SD 主机校验扇区 CRC16。

马林巴采用 one-shot 自然衰减，松键不截断；结束记录放在最后一音之后约 1.2 秒，给尾音留出时间。钢琴 `PIANO.BIN` 仍用 P88S 和 A0 起始索引，原格式不变。两种模式共用读取/调度模块，但按当前模式选择文件名并校验不同魔数。

## 从参考音频转录

`tools/make_ringtone_score.py` 读取本地参考 PCM，用立体声幅度谱检测独立音高的上升沿，分离检测到的同时发声，保留重复乐句。核实的音高为 G4、B4、D5、E5、G5、B5；用这六个音高约束检测以排除短窗谱泄漏。该流程是有音高词表约束的离线转录，不是适用于任意音频的通用转录器。

输出有 51 次 note-on、51 次 note-off 和 1 条结束记录，共 840 字节、约 9.355 秒（包含起始时间和末尾尾音时间）。`sd_card/RINGTONE.json` 保存全部时间、力度和来源哈希。转录得到的节奏、力度是估计；源录音中的背景噪声、混响和原音色不会逐样本重现。试听代表当前模态马林巴按这些指令演奏的结果。

当前核心在原 C2–F5 上补齐 F♯5–B5，以支持铃声里的 G5/B5；这些参数同样来自项目 Iowa C5B5 的逐音 PCM 拟合。原 42 音参数逐项保持一致，KEY1 范围不变。源录音和旧 IMA ADPCM ROM 只保留作参考；板级播放没有实例化 `ringtone_pcm_player`，不再读取铃声音频 ROM。

## 写卡与验证

`tools/copy_ringtone_to_sd.ps1 -DriveLetter H` 验证可移动 FAT 卷，必要时先备份旧的同名文件，然后写入、刷盘并读回 SHA256；同时核对 `PIANO.BIN` 哈希不变。写卡结果保存在 `sd_card/RINGTONE_SD_WRITE.json`。不格式化、不覆盖其他卡上文件。

`sim/run_ringtone.ps1` 覆盖 FAT16/FAT32、完整 51 音事件顺序和力度、加载时停止、播放时停止、重播、EOF、复位、KEY1 隔离，以及缺文件、错魔数、越界音符和 CRC 错误。SD 集成测试加速毫秒计时，用于验证逻辑和控制；完整音频测试按真实采样率调度同一组事件。

`sim/tb_ringtone_synth.sv` 导出完整 152263 个实际 RTL 采样，`tools/check_ringtone_synth.py` 与独立复音整数模型逐点核对。该测试只省略采样间空闲时钟，不改变合成状态更新或事件的采样时间。试听 `sim/ringtone_sd_realtime.wav` 不做逐音归一化，报告为 `sim/ringtone_sd_audio_report.json`。48 音同时触发测试耗时 2496 时钟，小于每帧 3072 的预算。

位流由 `tools/build.tcl` 覆盖生成，并自动检查 50 MHz 布局时序。卡上文件已经写入且读回校验；本次未烧录 FPGA、未进行板上 SD 总线或音频实测。
