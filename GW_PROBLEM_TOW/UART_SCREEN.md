# 淘晶驰串口屏选曲接口

当前返回快照在原有六个数字控件之后追加 `every.tNote.txt="音名"` 和三个 FF，自动显示实际选中音符。every 页进入后的查询代码及控件设置见 [UART_THREE_KEYS.md](UART_THREE_KEYS.md)。

新增三键 88 音试听：CMD 40/41/42（上一个/下一个/播放），完整按钮代码及操作见 [UART_THREE_KEYS.md](UART_THREE_KEYS.md)。新增状态 n0=4 表示单音试听中。下文“第一版只实现选曲/停止/查询”为历史描述。

目标屏：TJC8048X270_011C。FPGA 接收选曲/停止/查询命令，读取开发板 SD 卡的乐谱事件并实时合成；UART 不传送音频。实体 KEY0 仍播放/停止安卓铃声，KEY1 仍为 C2–F5 的 42 音试听，KEY2 复位。

## 接线与串口

默认约束依据工程内 `Tang_Mega_NEO_Dock-60K_31004_Schematics.pdf` rev1.4，第 7、19 页，使用 PMOD1（J8），不是板载 BL616 的 USB UART。

| 屏幕端 | 开发板端 | FPGA 球位 |
|---|---|---|
| TX | J8 第 11 脚，PMOD1_IO0，`uart_rx` | B18 |
| RX | J8 第 12 脚，PMOD1_IO1，`uart_tx` | B17 |
| GND | J8 第 3 或第 4 脚，GND | — |
| VCC | 屏幕按铭牌要求单独供电；采用合适的 5 V 电源 | 不接 FPGA IO |

J8 第 1、2 脚是 3.3 V 电源，不能当作 GND，也不要用它给这块 7 寸屏供电。按连接器的实际脚号辨认，不按杜邦线颜色或目测左右顺序接线。该接口为 3.3 V TTL UART；TX/RX 交叉连接并共地。PMOD1_IO0/1 与 SDRAM1/摄像头的复用信号不能同时使用。

串口：9600 bit/s，8 数据位，1 停止位，无奇偶校验，无流控。屏幕保留 `recmod=0`。屏幕用 `printh` 发原始命令帧；FPGA 返回原生 ASCII 控件赋值，并附 `FF FF FF`，屏幕无需解析自定义返回帧。

淘晶驰官方初始化示例及波特率说明：[资料中心](https://wiki.tjc1688.com/QA/baudrate.html)。厂商关于屏幕/MCU 交互的说明：[串口屏与单片机的交互指令](https://www.tjc1688.com/contents/25/134.html)。

## 第一版命令

固定 10 字节，全部以十六进制表示：

```text
A5 5A 01 SEQ CMD P0 P1 P2 SUM 0D
```

`SUM=(01+SEQ+CMD+P0+P1+P2)&FF`。`SEQ` 是回显序号，不承担自动去重；屏幕的固定按钮代码可以用 00。未使用参数必须为 00。序号可以从 00 到 FF，包括 A5/5A/0D；固定长度接收不需要转义。

| CMD | 功能 | P0 | P1/P2 |
|---|---|---|---|
| 01 | 查询状态 | 00 | 00/00 |
| 10 | 播放指定曲目 | 01、02、03 | 00/00 |
| 11 | 停止并清音 | 00 | 00/00 |

| 曲目编号 | 开发板 SD 根目录文件 | 实时音源 |
|---|---|---|
| 01 | ANDROID.BIN | 马林巴，M42S |
| 02 | RINGTONE.BIN | 马林巴，M42S |
| 03 | PIANO.BIN | 钢琴，P88S |

这三个现有 BIN 无需重新转换。文件仍保存在开发板的 SD 卡，不是屏幕的 SD 卡。选曲通过硬件表映射 FAT 8.3 文件名，不向 FPGA 发送中文文件名。

重复选择正在加载/播放的同一首不会重启；选择其他曲目会清音、复位读谱和合成状态，然后从新曲开头播放。需要同曲重播时先停止再播放。默认配置下结束自动返回手动试听，保留最后曲目编号；停止则把编号清零。

按键间隔建议至少 300 ms；查询通常 1 秒一次即可。不要使用持续高速重发。反馈队列可缓存 16 个快照；过载后丢弃无法排队的请求，停止命令仍执行，恢复发送后通过错误码 60 报告溢出。溢出标志保留至 KEY2 复位。校验错、版本错、帧尾错、UART 停止位错的帧不执行也不回复；半帧 20 ms 无新字节会丢弃，随后重新找帧头。

第一版只实现选曲/停止/查询。上一轮方案中的单音、音量等功能保留命令空间，当前发送会回复“不支持”，不会改变音频。

## 屏幕工程设置

在 USART HMI 中新建/打开对应型号的工程，页面名称使用 `page0`。创建 6 个数字控件 `n0`～`n5`，`vscope` 全部设为 `global`，初值均为 0。这些名称是 FPGA 返回接口的一部分；即使隐藏数字控件也要保留它们。若名称不同，需要同步修改 `tjc_status_tx.v`。

Program.s 的全局声明保留模板内容，在最终 `page 0` 之前设置：

```text
bauds=9600
recmod=0
bkcmd=0
page 0
```

`page 0` 后面的初始化代码不会执行，不要把设置写到它后面。关闭按钮事件中的默认“发送组件 ID”，只在**触摸弹起事件**填入下列一行 `printh`，不要在按下和弹起各发一次。

安卓铃声按钮：

```text

```

苹果铃声按钮：

```text
printh A5 5A 01 00 10 02 00 00 13 0D
```

钢琴曲按钮：

```text
printh A5 5A 01 00 10 03 00 00 14 0D
```

停止按钮：

```text
printh A5 5A 01 00 11 00 00 00 12 0D
```

查询按钮，以及 page0 的“后初始化事件”（确保控件已建立后查询）：

```text
printh A5 5A 01 00 01 00 00 00 02 0D
```

独立代码片段放在 `screen/tjc_uart/`。这是可复制的屏幕脚本，不是已经由 USART HMI 编译的 .HMI/.TFT 文件；需要在屏幕工程内创建上述控件并编译下载。

## 返回值

每次快照依次发送以下六条 ASCII 指令，每条以三个 FF 结束；数字使用十进制。

```text
page0.n0.val=<状态>
page0.n1.val=<曲目编号>
page0.n2.val=<错误码>
page0.n3.val=<命令结果>
page0.n4.val=<SEQ>
page0.n5.val=<CMD>
```

| 控件 | 含义 |
|---|---|
| n0 | 0=手动/空闲，1=加载中，2=播放中，3=播放错误 |
| n1 | 0=无选择，1=安卓，2=苹果，3=钢琴 |
| n2 | 0=无错误，其余见下表 |
| n3 | 0=命令已接受，1=参数错误，2=命令不支持；主动快照的 3 表示反馈溢出 |
| n4 | 命令回复回显请求 SEQ；主动状态快照为 0 |
| n5 | 命令回复回显 CMD；主动状态快照为 129（十六进制 81） |

n5 在六个数字字段中最后写入，随后更新 every.tNote 音名文本。上电、实体按键导致的状态改变、加载到播放、自然结束和错误都会主动上报；查询还能在屏幕先后上电或重新进入页面后重新同步。命令接受成功与 SD 加载成功是不同阶段：先看到加载中，再看到播放中或错误。

| n2 错误码（十六进制；控件显示十进制） | 含义 |
|---|---|
| 1x | SD SPI 错误，低 4 位是 sd_error_code |
| 24（十进制 36） | FAT 文件不存在 |
| 2x 其他 | FAT 错误，低 4 位是 fat_error |
| 31（十进制 49） | 乐谱头/格式不匹配 |
| 3x 其他 | 乐谱解码错误，低 4 位是 score_error |
| 40（十进制 64） | 事件队列/顺序错误 |
| 50（十进制 80） | 合成计算超时 |
| 60（十进制 96） | 串口反馈队列溢出，降低发送频率 |

错误在关闭 SD 通路前锁存，避免复位读卡器后丢失原因。停止、新曲开始或 KEY2 会清除播放错误。UART 反馈溢出单独锁存到 KEY2。

可增加文本控件 t0 和 200 ms 定时器，把 `n0.val` 映射为 READY / LOADING / PLAYING / ERROR；示例在 `screen/tjc_uart/status_timer.txt`。六个数字控件也可以先直接显示，便于调试。

## 源码与验证

- `uart_rx.v`：两级同步、起始位确认、8N1 接收、停止位检查和 break 恢复。
- `uart_tx.v`：ready/valid 字节发送。
- `uart_score_control.v`：滑动帧同步、校验、超时、命令检查及反馈队列。
- `tjc_status_tx.v`：生成屏幕原生控件赋值指令。
- `piano_score_player.v`：统一选曲、实体按键、SD/乐谱格式和合成器路由。

运行 `powershell -ExecutionPolicy Bypass -File sim/run_uart.ps1`，验证物理串行收发与三曲选播。协议仿真使用真实 50 MHz/9600；集成仿真仅加速 UART 和谱面时间，使用现有歌曲的音高/力度构建短 FAT 夹具，不改写 SD 文件。覆盖错误帧、半帧超时、break、噪声重同步、非法参数、原生 ASCII 返回、反馈排队与溢出时停止、三种文件/音源选择、自然结束、切歌、加载中停止、缺文件/格式错误、实体按键及复位。

构建入口仍为 `tools/build.tcl`，位流仍覆盖 `impl/pnr/GW_PROBLEM_TOW.fs`。硬件接线和屏幕烧录后的实测需要在实际设备上完成。

2026-10-23 验证结果：UART 协议与三曲集成、七项基础回归、完整钢琴读谱回归、完整安卓铃声 FAT16/FAT32 回归均通过。原位流已覆盖，50 MHz 时序通过，Fmax 50.007 MHz、Setup/Hold 违规 0/0，裕量较小。详见 `VERIFICATION.md` 和 `output/uart_build_manifest.json`。
