# 验证记录

验证日期：2026-10-18。
工具：Gowin IDE V1.9.12.03，ModelSim SE-64 2020.4，Icarus Verilog，Python/NumPy。

## 已完成的功能验证

`sim/run.ps1` 中的四个 ModelSim 测试全部通过：

- `tb_keys`：去抖、按住不重触发、88 音循环、松开事件、停止后的按键锁定。
- `tb_synth`：A/D/S/R、A 期间松键、R 尾音与新音符重叠、88 声部、实时音高倍率和强制停止。
- `tb_limiter`：正负数四舍五入、正常主增益、过载限制和 16 位输出边界。
- `tb_dac`：每帧 3200 时钟、16 位 LSBJ、左右声道一致和整帧静音。

相同四个行为测试也已通过 Icarus 交叉检查。
现场波形脚本已经在 ModelSim 中实际执行通过，并保存 `sim/realtime_evidence.wlf`。

`sim/clock.ps1` 使用 Gowin 官方 `gw5a/prim_sim.v` 编译实际 PLL 链，
在约 3.54 ms 仿真时间内完成校准、锁定和频率检查。
数字模型测得周期 6.510 ns、3200 周期 20832 ns；与理想值之差来自原语模型的皮秒舍入。
硬件配置的数学频率为 153.6 MHz / 3200 = 48 kHz，实际值跟随板载晶振。
该测试没有定义 `SIM` 宏缩短厂商校准等待，避免等待时间短于原语模型锁定时间导致假失败。

## 连续音频与数学核对

`tb_demo` 使用默认包络和实际 3200 周期帧间隔，生成 126010 帧，约 2.625 秒：
A4 按住/松开、A 大三和弦、C8、88 键同时发声、强制停止。
结果见 `sim/tb_demo.log` 和 `sim/audio_report.json`：

| 项目 | 实测 |
| --- | --- |
| 最大活跃声部数 | 88 |
| PCM 绝对峰值 | 30000 |
| 限制器起作用帧数 | 11907 |
| 末端硬饱和或采样超期 | 未发生 |
| A4 前 24000 样本与独立模型最大差值 | 0 |
| C8 第 6/7/8 谐波折叠位置相对基频 | -109.15 / -94.52 / -103.56 dB |

频谱值为加窗单频测量，不是模拟 DAC 的失真指标，也不是完整混叠频谱的全带宽噪底。
八个 A4 谐波与三和弦三个音高均通过检出检查。

生成的 `sim/realtime_synth_demo.wav` 为左右相同、48 kHz、16 位的仿真试听结果，
不被 FPGA 工程读取。完整逐样本检查模型位于 `tools/analyze_audio.py`。

## 实现状态

Gowin 综合、布局布线、位流生成均已通过。最终布局布线时序报告：

| 项目 | 结果 |

| Hold 违例端点 | 0 |
| 全 88 声部触发至 PCM 就绪最大延迟 | 3121 周期 |
| 每采样帧预算 | 3200 周期 |

| PLLA | 2 / 8 |

位流为 `impl/pnr/GW_PROBLEM_TOW.fs`。`tools/build.tcl` 在生成后自动运行
`tools/check_timing.py`，出现 Setup/Hold 违例或达不到目标频率即返回失败，
不能只依据存在 `.fs` 文件判断构建合格。

声部状态存储已使用同步 RAM，波表读出、插值、加权、包络和输出限制分别流水处理。
KEY0 清除状态有效标记，不给整块 RAM 增加异步复位；RAM 中旧内容会被忽略，
下一次触发从新相位和 Attack 开始。
完整音频测试与最终状态存储、流水线的功能保持逐点核对。

当前时序裕量较小，全负载也只剩约 79 个时钟周期的帧预算，
后续接入新模块时必须重新检查时序与 `deadline_error`，不应在现有循环中直接插入额外长流程。

工具保留一条 `PR1014`：V22 输入时钟使用一般布线资源，可能增加延迟或偏斜。
这是当前板卡固定时钟管脚的实现警告；没有改动板卡引脚，也没有把音频运算路径设为假路径。
异步按键输入以及复位同步器的异步清除端被排除出同步时序检查，
复位释放由音频时钟域的四级寄存器完成。最终同步路径仍要求正常满足时序。
