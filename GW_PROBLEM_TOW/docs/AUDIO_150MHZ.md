# 150 MHz原生音频域

## 时钟与采样

系统控制仍为50 MHz：压力ADC扫描、UART屏幕、蓝牙、SD调度、长按灯和动态指引灯不倍频。
只有合成器、限幅器、数字效果器及PT8211改用官方PLL产生的150 MHz。
PT8211仍每3072个音频时钟产生一帧，原生采样率为48828.125 Hz，双声道输出相同16位PCM。
这不是将旧PCM重复三遍或插值升采样：DDS相位、分音、模态、噪声和混音均逐个新样本运算。

钢琴频率字比例由193274调整为64425，马林巴使用新增marimba48_48828.hex；
原有五张表逐字节保留，生产路径不额外例化一套旧马林巴。
后续ROM优化只重排参数并共用正弦读口，当前为59个RTL输入，见ROM_SHARING.md。
ADSR、分音衰减、持续力度平滑及限幅释放每三样本更新一次，保留原来的实际时间尺度。
马林巴琴体滤波极点按新采样率重算；模态结束后清尾384帧，仍约7.86 ms。
功放启动等待按三倍时钟周期计数，实际等待时间不缩短。

## 官方IP

| 路径 | 配置 |
| --- | --- |
| ip/audio_pll150/audio_pll150.ipc | Gowin_Audio_PLL150，输入50 MHz，输出150 MHz |
| ip/audio_fifo32/audio_fifo32.ipc | Gowin_Audio_FIFO32，32位×16，双时钟、独立复位、标准读取 |

生成的官方.v用于综合，FIFO的.vo用于ModelSim，仿真同时加载Gowin官方gw5a原语库。
PLL包含官方校准初始化逻辑，锁定后再同步释放音频复位。
FIFO无额外输出寄存，Almost_Full阈值14，反馈链路预留两个PCM位置。
生成脚本tools/generate_audio150_ip.tcl仅使用output/audio150/ip_project中的临时工程，
不是主工程编译入口；正常编译直接使用已经加入.gprj的IP文件，无需每次重新生成。
最终重新生成或修改IP后须重跑专项仿真。

## 跨域与故障

audio_domain_bridge内有两只官方双时钟FIFO：
50→150 MHz按顺序传递模式、效果设置和音符事件；
150→50 MHz返回实际被音源接受的事件确认、忙/错误状态及DAC已锁存样本。
多位音符/力度/PCM不直接逐位同步。返回PCM优先于事件确认，正常背压不会丢失音符。
瀑布流和演奏指引根据实际事件确认更新，不根据尚未被音源接受的请求提前亮键。
频谱/波形在50 MHz使用返回的真实DAC样本，不分析未来样本或另行重合成的PCM。

停止、换曲及切音源刷新传输代次，清除旧队列；旧确认不能重新点亮琴键。
PLL失锁立即复位FIFO和音频域，重新锁定后先同步配置，再允许新音符。
错误0x63（十进制99）表示跨域溢出或运行中时钟失锁，锁存静音，可停止/重选/KEY2恢复。
原0x61压力溢出、0x62效果超期保持原含义。

## 效果与画面

原声、延迟、震音、颤音及0x51/0x52指令不变，串口屏不需要修改。
约300 ms延迟为14648样本，最长4秒尾音为195312样本。
共享效果RAM扩为16384×16（32 KiB），颤音中心240样本、深度96样本，
LFO仍约5 Hz，渐变仍按原实际时间。固定整帧效果流水延迟由61.44 us变为20.48 us；
这只是效果流水，不等于端到端按键延迟。

分析FFT仍为1024点，采样块约20.972 ms，频率间隔47.684 Hz，奈奎斯特频率24.414 kHz。
波形512样本约10.486 ms；坐标同步改为0～24 kHz及0～10 ms。
频率覆盖扩大三倍，但固定FFT点数下分辨率变粗三倍，不能宣称分辨率也提高。
FFT计算仍在50 MHz，刷新还取决于过零触发、计算及视频换帧确认。
视频仍为108/540 MHz，钢琴瀑布流滚动速度、SD毫秒时间戳和灯光刷新速度不变。


真实顶层压力/SD/UART/双声道DAC及FFT完整像素。日志与仿真WAV在output/audio150。

本轮没有主工程综合、布局布线或烧录，旧.fs不包含此修改。用户重新载入.gprj后最终编译。

同时检查剩余BSRAM/DSP、PLL资源及PT8211实际输出。不能以仿真或旧Fmax代替新时序报告。
