# 串口屏数字效果器

当前四种互斥模式：0原声、1延迟、2震音（Tremolo）、3颤音（Vibrato）。钢琴/马林巴、压力演奏、
UART试听及PN/MB播放共用。没有恢复DDR或用SD缓存音频，也没有改引脚。
当前生产音频域为150 MHz、原生48828.125 Hz，控制域仍50 MHz，详见AUDIO_150MHZ.md。

## 演奏行为

- 上电/KEY2默认原声，效果量默认30；原声模式忽略效果量。
- 模式和效果量可以在演奏中调整，不换音色、不换曲、不重新校准或重触发音符。
- 0～100控制效果深度，不是反馈系数。延迟最大湿声权重为125/256；震音控制音量起伏，颤音控制音高摆幅。
- 效果量每三个音频样本最多变化一个Q0.8单位，切模式先淡出、换缓存状态、再淡入，
  颤音另有按相同控制速率的256步淡入/旁路淡出，完整切换仍最多约31.5 ms。屏幕回显目标设置，不是中间渐变值。
- 普通松键、音源自然衰减和SD自然结束后，效果器继续处理零输入，保留效果尾音。
- 停止、新曲、切乐器、新UART试听或KEY2清除旧效果状态；模式/效果量切换本身不停止音源。
- 停止不会重置所选效果；KEY2才恢复原声和30。切音色保留效果选择但不保留旧尾音。
- 效果尾音可以在n0已回空闲时继续；频谱/波形仍观察最终DAC声音。
- 瀑布流只观察钢琴原音符事件，不为回声或音量/音高调制生成假按键。长按灯仍表示物理按压时长。

## 固定预设

| 模式 | 算法 |
| --- | --- |
| 原声 | 样本值直通，无湿声 |
| 延迟 | 约300 ms、0.5反馈的环形缓存回声 |
| 震音 | 约5 Hz三角LFO调制音量；效果量100时音量约为原声的3%～100%，30时约71%～100% |
| 颤音 | 约5 Hz调制分数延迟，稳定后100%输出调制信号；效果量控制音高摆幅，无反馈 |

颤音的中心延迟为240样本（约4.9 ms），最大摆幅约±93.75样本。
在效果量100下，440 Hz测试音约在423～458 Hz之间变化，稳态不掺混原声。
效果量0经平滑后逐样本原声直通；震音不产生尾音，颤音只保留短缓存中的声音。
延迟尾音窗口195312样本（最多约4秒）、颤音338样本（约6.92 ms），最后有效输入后倒计时，
避免定点反馈的极小残留永久发声；输入幅度不超过4个LSB不会续期窗口。
保留原公共限幅器，效果存储及最终干湿混合另作16位饱和保护，绝不回绕。
当前单声道处理复制到左右DAC，与原硬件输出一致，不假称立体声效果。

一块16384×16同步RAM（32 KiB）互斥复用，目标是推断块RAM，不异步清空整块存储单元。
停止/换模式只清小量指针、有效长度和状态，旧单元在重新覆盖前视为零。
默认原声也经过固定整帧流水，额外约20.48 us延迟；三种模式干湿信号保持样本对齐。
效果FSM经时序流水修正后仿真最多16个150 MHz时钟，不占用钢琴/马林巴内部计算状态机。
内部计算仍在下一DAC帧前完成，不额外增加整帧延迟；新增采样边界控制快照，
改变效果量不会撕裂正在计算的样本。细节及未完成的物理时序确认见TIMING_150MHZ.md。
以上是代码和周期预算，不是综合资源或物理时序报告。当前预设针对150 MHz/3072周期音频帧，
300 ms延迟14648样本，5 Hz LFO和渐变时间已同步调整。预计RAM用量不能替代最终Gowin报告。

## 串口屏协议

保持原115200/8N1、recmod=0和10字节v1帧；P1/P2必须为0：

```text
A5 5A 01 SEQ CMD P0 00 00 SUM 0D
SUM=(01+SEQ+CMD+P0)&FF
```

| CMD | P0 | 功能 |
| --- | --- | --- |
| 51 | 0～3 | 原声/延迟/震音/颤音 |
| 52 | 0～100 | 效果量 |

```text
// 原声
printh A5 5A 01 00 51 00 00 00 52 0D
// 延迟
printh A5 5A 01 00 51 01 00 00 53 0D
// 震音
printh A5 5A 01 00 51 02 00 00 54 0D
// 颤音
printh A5 5A 01 00 51 03 00 00 55 0D
// 效果量50（十六进制32）
printh A5 5A 01 00 52 32 00 00 85 0D
```

无效模式/超出100/非零保留参数返回结果1，保持旧设置；反馈队列满时不接受普通新设置，
停止仍有效。不要无间隔发送。新错误0x62（十进制98）表示效果器样本处理超期，静音并等待停止/复位恢复。

原page0.n0～n5和两个乐器/音名文本含义不变，每个反馈快照新增：

| 全局数字控件 | 含义 |
| --- | --- |
| page0.n6 | FPGA接受的效果模式，0～3 |
| page0.n7 | FPGA接受的效果量，0～100 |

查询0x01和参数设置后的回复均携带n6/n7，数值与其他字段一起锁存。
旧HMI没有n6/n7时新增赋值无法显示，因此需要按下面步骤增加控件。

## 在现有HMI增加控件

本仓库未提供用户实际.HMI工程，以下是可粘贴事件脚本，不是已编译HMI/TFT，
本次未在淘晶驰IDE或实屏编译验证。不要以仿真通过代替屏幕工程编译。

在page0创建以下控件，变量/数值设为全局，保留所有原控件：

| 类型/名称 | 设置与事件 |
| --- | --- |
| 数字n6、n7 | 接收FPGA反馈；n6可隐藏，n7作为实际效果量显示 |
| 按钮bFx0～bFx3 | 标签原声/延迟/震音/颤音；弹起事件分别粘贴effect_original/delay/tremolo/vibrato_release.txt |
| 滑块hFx | minval=0、maxval=100；按下贴effect_slider_press.txt，弹起贴effect_slider_release.txt |
| 数值变量vaFxDrag、vaFxSent、vaFxValue、vaFxSum、vaFxWait、vaFxShown | 默认0，全局 |
| 定时器tmFx | 100 ms；事件粘贴effect_timer.txt |

页面后初始化追加effect_page_postinitialize.txt，不要删除原页面初始化。
原每秒/200 ms状态查询可保留；初始化只查询，不擅自覆盖FPGA当前配置。
字库需包含“原声延迟震音颤音效果量”。关闭新增按钮/滑块默认发送组件ID。
旧屏幕模式2/3的帧不变，无需改协议；请将原“混响/合唱”按钮文字改为“震音/颤音”。
旧effect_reverb_release.txt/effect_chorus_release.txt保留为相同帧的兼容脚本。
按钮背景按n6更新，绿色为FPGA接受的模式，其余灰色；不只根据本地触摸高亮。

拖动仅每100 ms检查一次，值变了才发送；松手无条件补发最终值。
动态发送用prints输出数值的低1字节，不是ASCII数字，也不是完整4字节数值。
校验和为83+滑块值，0～100范围不溢出一字节。
等待接受值期间不让旧反馈拖回滑块，最多等待1秒后按FPGA实际n7重新同步；
队列过载/错误会保留真实设置，不伪装为设置成功。

## 主机工具及仿真

```powershell
# 不指定Port只打印帧，不访问串口
powershell -File tools/send_uart_command.ps1 -Command EffectTremolo
powershell -File tools/send_uart_command.ps1 -Command EffectVibrato
powershell -File tools/send_uart_command.ps1 -Command EffectAmount -Amount 50
powershell -ExecutionPolicy Bypass -File sim/run_effects.ps1
```

逐样本参考覆盖三种算法、缓存回卷、0～127全部硬件输入量（超过100钳位）、
饱和、清除、模式/量渐变及尾音超时；屏幕协议仅接受0～100。
检测震音包络深度、颤音实际过零周期/音高范围和周期峰值，覆盖正负满幅持续输入、所有模式互切及零效果量直通。
真实UART集成验证压力钢琴演奏不中断、马林巴、自然SD结束后回声、停止/切音色清除和实际DAC双声道。
output/audio_effects下有日志、参考/RTL WAV和输入指纹。WAV是数字仿真，不是板上实录。
verification.json核对原五张音频ROM及其余存储/蓝牙、瀑布流与备份逐字节一致。
原生音频算法、SDC及官方IP改动另由output/audio150审计；旧50 MHz独立单元仍按原参数校验，
不将它的16 KiB缓存或WAV采样率误认为当前生产配置。
后续动态指引灯对顶层和CST的改动另由tools/check_key_guide.py核对，不再与效果器加入前顶层作相等断言。
音频门控寄存及SD几何检查寄存对应的两份源码单列于timing_pipeline_changes，不列入未修改文件。
最终综合、布局布线和资源用量以Gowin报告为准，构建入口为tools/build.tcl。
实际听感及TJC屏幕工程仍需实机确认；仿真通过不能代替上板试听。
