# 固定槽位蓝牙上传 v2

## 接线与使用范围

蓝牙模块直接例化在顶层 `GW_PROBLEM_TOW.bluetooth_upload`，只上传乐谱，不控制播放。
50 MHz系统时钟，KEY2复位，115200/8N1，FPGA TX=D15接HC-05 RX，RX=D16接HC-05 TX。
串口屏仍使用B17/B18，只播放PN/MB编号曲目；单音试听及显示命令保留。

| KIND | 编号 | 根目录文件名 | 格式 |
| --- | --- | --- | --- |
| 1 | 1～100 | PN001.BIN～PN100.BIN | P88S v1 |
| 2 | 1～100 | MB001.BIN～MB100.BIN | M42S v1 |

每槽文件长度固定100 KiB=102400字节，实际乐谱长度另存有效记录。
没有20 KiB的人为上限；实际长度必须为24～102400且满足原事件格式。
不是WAV，也不是把任意文件改名为BIN就能播放。

上传前用串口屏停止SD播放；最终回复后再播放。按操作者人工互斥，不增加同时读写调度。
上传期间不要按KEY2、拔卡、断电、开始播放或更换卡。蓝牙只负责传输，不发送屏幕播放命令。

## 先准备SD布局

不能在任意普通FAT卡上直接按固定LBA写入，否则可能覆盖目录或别的文件。
本版通过离线工具建立新的标准MBR/FAT32镜像，预先创建200个正常文件并固定其簇链：

```powershell
python -B tools/slot_card.py --initialize --image output/slots_numbered_3GiB.img --size-mib 3072
python -B tools/slot_card.py --image output/slots_numbered_3GiB.img
```

工具仅打开普通`.img`文件，拒绝物理设备路径，默认拒绝覆盖已有镜像。
默认大小3072 MiB，即3 GiB；写镜像前必须核对目标卡实际字节数。
只建立200个PN/MB占位文件，不再加入原三首。稀疏属性不保证Windows上的实际磁盘占用，生成前预留完整容量。
已经初始化并成功上传的卡无需重做；前200个槽位地址和有效记录格式保持兼容。
现有旧镜像不自动改写，卡上即使仍有旧三首目录项，FPGA也不会查找或播放它们。

**本工具不会格式化或写入你的物理SD卡。以后将镜像整盘写入卡会替换该卡原有分区和文件，必须先备份并核对目标盘。**
本轮没有自动执行写物理卡操作。
写镜像时必须写入其完整逻辑内容，不能使用跳过零块的模式，否则旧有效记录和数据可能残留。

电脑会正常识别200个100 KiB的BIN文件，包括尚未上传内容的占位文件。
是否可播放不根据文件名是否存在判断，而根据FPGA私有有效记录。
空占位文件虽然在电脑上可见，但串口屏点击没有效果。

布局采用512字节扇区、32 KiB簇；每文件占4个连续簇，即128 KiB物理步长，
其中前100 KiB是文件数据，后28 KiB是该文件最后一个簇内的分配余量。
这样仍然是标准FAT文件，同时FPGA用移位即可计算槽位地址。200槽实际分配25 MiB。
FPGA上传时只清零前100 KiB和自己的有效记录，不改FAT、根目录或邻槽。

不要在电脑删除、重命名、改变这些文件大小、重建分区或做整理碎片。
普通“用新小文件覆盖旧文件”可能释放原簇链并重分配，不能作为槽位上传方式。
通过蓝牙上传更新内容；电脑可以浏览、复制导出。
从电脑导出的文件带100 KiB零填充，发送工具会按事件头恢复实际长度再上传。
PC直接改数据但不改有效记录会导致播放CRC失败；换卡或外部修改后按KEY2重建缓存。

写入前硬件检查布局描述、MBR、BPB、选定目录项名称/长度/起始簇和两份FAT的4个链接。
发现移动、改名、改长度、只读或损坏时，拒绝开始，不清零目标。
已移除普通FAT16/FAT32卡的旧文件查找回退；播放和上传均要求本固定槽位布局。
不支持exFAT。

## 手机与PC发送流程

```text
BEGIN控制帧 -> FPGA校验并使旧槽无效、清零整个100 KiB -> READY
手机连续发送恰好N个原始文件字节，无DATA帧、无每块ACK
END控制帧 -> FPGA等待SD写完、核对CRC/格式、提交有效记录 -> 最终结果
```

READY之前不能发送正文。READY成功只是“槽位准备好”，不代表文件已上传完成。
BEGIN和END是控制消息，不写进BIN；槽位里只有原文件字节与尾部零填充。
正文无需512字节分包，蓝牙/SPP或操作系统自己拆分传输不影响FPGA。
保留BEGIN中的实际N，是为了准确区分原始正文与后续END，发送工具自动填写。
文件本身的格式头仍然保留，因为解码器需要它。

```powershell
# 仅检查，不开串口、不改卡
python -B tools/bluetooth_upload.py D:/scores/PN001.BIN --instrument piano --number 1
# 实际上传时才需要pyserial和端口参数，COM8仅为示例
python -m pip install pyserial
python -B tools/bluetooth_upload.py D:/scores/PN001.BIN --instrument piano --number 1 --port COM8
```

手机实现相同的BEGIN/READY、原始文件、END/结果流程即可，普通裸文件发送不能省掉首尾控制。
不需要在DATA阶段与FPGA交互。原hc05_test的PING/LED/ECHO文本命令没有并入。
115200/8N1理论净速率11520字节/秒，20 KiB正文约1.78秒，100 KiB正文约8.89秒，另加清零和写卡等待。
PC工具BEGIN最多等300秒，END每次最多120秒，控制帧最多尝试3次。

FPGA有32 KiB块RAM FIFO，可缓存你预计的不超过20 KiB的整份正文。
超过32 KiB的文件边收边写仍可上传到100 KiB，但不能保证在任意长SD停顿下都不溢出。
无逐块流控，FIFO满、UART帧错、CRC/格式错或写卡失败都明确失败，不把残缺正文标为有效。
收到失败应重新BEGIN并重传整个文件，不支持断点或单块重试。
DATA中不能插入CANCEL控制字节，否则会当作文件正文；中断时停止发送并等待30秒空闲超时。

## 控制协议

与旧v1分包协议不兼容，发送端必须更新为v2。多字节整数均为小端，SEQ固定0。

```text
请求：A5 5A 02 OP 00 00 LEN(u16) PAYLOAD[LEN] CRC16(u16)
回复：5A A5 02 OP 00 00 STATUS DETAIL 00 00 CRC16(u16)
```

控制负载最多10字节，回复固定12字节，两个保留字节为0。
CRC16/XMODEM：多项式0x1021，初值0，无反射、无最终异或，覆盖请求头和负载；
回复覆盖前10字节。ASCII `123456789`的CRC16为0x31C3。
正文不额外包装CRC16，整文件CRC32采用IEEE/zlib，等于`zlib.crc32(实际文件字节)`。
SD扇区链路自身仍有CRC16、CMD24数据响应、busy等待和CMD13检查。

| OP | 负载 | 成功回复 |
| --- | --- | --- |
| 1 BEGIN | KIND u8、编号u8、N u32、CRC32 u32，共10字节 | 目标100 KiB清零完成后的READY |
| 3 END | 无 | 正文完整、CRC/格式通过、有效记录写入完成 |
| 4 CANCEL | 无 | 清零完成后、正文开始前，或正文收齐后取消 |

没有OP=2 DATA，也没有NEXT块序号。仅在等待首字节时支持完全相同的BEGIN重试，
不会再次清零；最终成功END可重复回复，直到新会话或复位。
控制半帧0.5秒无新字节则丢弃；正文或等待首尾控制30秒无新字节则取消。
准备、正在等待结束写卡及回复发送时间不计入正文空闲超时。
KEY2清除会话/FIFO，不支持跨复位续传。

| STATUS十进制 | 含义 |
| --- | --- |
| 0 | READY或最终成功 |
| 1 | 控制帧CRC错误，可重发控制帧 |
| 2 | 不支持的版本/操作/参数/长度 |
| 3 | 正文尚未收齐 |
| 4 | 无会话 |
| 5 | 已有不同会话 |
| 6 | 整文件CRC失败 |
| 7 | 乐谱格式失败，DETAIL是原解码器错误 |
| 8 | SD或布局错误 |
| 9 | 已取消 |
| 10 | 空闲超时，主动回复OP=4 |
| 11 | 接收FIFO溢出 |
| 12 | UART帧错误 |

存储DETAIL十六进制：`1x`为原SD错误，如`12`忙超时、`14`状态错误、`19`写响应拒绝；
`21`未准备卡/描述或几何损坏，`23`目录项移动/改名/改长/只读，`24`FAT链接不符，
`26`槽位长度非法，`2F`内部状态错误。

## 有效性与失败边界

覆盖不是保留旧文件的事务：布局检查通过后先把目标有效记录清零，再清零100 KiB。
READY时旧内容已被销毁。上传失败、超时、KEY2或断电不恢复旧文件。
新文件只在全部正文写完、CRC/格式通过、有效记录成功提交后可播放。
播放前再次核对实际正文CRC32，随后只向解码器输出真实N字节，不把100 KiB零填充当事件。
失效时清屏幕侧的编号缓存，成功时再置位，避免同名旧文件仍被认为有效。

私有信息位于分区前的MBR间隙，不能搬动或清理：

| LBA | 内容 |
| --- | --- |
| 0 | 标准MBR，FAT32分区从2048开始 |
| 1 | GW100K02布局描述，前60字节CRC32后存于偏移60 |
| 8～207 | 每槽一个512字节GWSLOT02有效记录 |
| 2048起 | 标准FAT32卷、两份FAT、固定根目录和文件簇 |

有效记录前28字节为8字节magic、版本u32=2、槽索引u32、实际N u32、
正文CRC32 u32、有效标志u32=0xA55AA55A；偏移28存记录CRC32，其余补零。
记录无效或不存在则视为空槽。槽索引0～99是PN，100～199是MB。
布局描述具体字段由`tools/slot_card.py`与`slot_card_query.v`共同定义并由仿真核对。

这不是断电原子存储。SD卡物理写失败或断电可能造成扇区不确定；
即使最终回复失败，若完整有效记录实际上已落盘，重启后也可能识别到完整新文件。
扇区CRC/记录CRC/正文CRC提供检查，不承诺对任意掉电时序保证旧版本或原子覆盖。
运行时不改FAT/目录，显著缩小写入范围，但仍应保留电脑上的源文件。

## 串口屏播放

旧0x10选曲命令已移除，返回不支持且不改变播放；编号选曲CMD=0x12，协议仍是串口屏v1：

```text
A5 5A 01 SEQ 12 KIND NUMBER 00 SUM 0D
SUM=(01+SEQ+12+KIND+NUMBER)&FF
// PN001.BIN
printh A5 5A 01 00 12 01 01 00 15 0D
// PN100.BIN
printh A5 5A 01 00 12 01 64 00 78 0D
// MB100.BIN
printh A5 5A 01 00 12 02 64 00 79 0D
```

NUMBER为十进制1～100，对应十六进制01～64。
200个按钮脚本仍在`screen/tjc_uart/numbered_buttons.txt`，放入触摸弹起事件并关闭组件ID发送。
反馈内部ID：0=无选择，PN为4～103，MB为104～203；保留编号偏移以兼容现有屏幕，不再使用1/2/3。
首次加载扫描200个有效记录并缓存；后续缺失编号请求忽略，不打断正在播放的曲目。
换卡后KEY2重新扫描。尚无缓存时只允许在空闲状态探测未知编号。

新编号钢琴曲可用实际PCM频谱/波形；旧第3首的固定ROM瀑布流不用于新曲。
本轮不改变五张音频ROM、视频谱面或两种音源。
