# SD钢琴跟弹指引

16颗串行彩灯对应16个物理压力键，第一颗对应第1键，最后一颗对应第16键。
默认关闭指引：动态灯全黑，PN/MB按原时间自动演奏。
通过串口屏开启后，PN曲目变为跟弹：乐谱只提供目标，不自动发声；人按压力键发声，
按对当前目标后进入下一组。MB仍正常自动播放且不亮指引灯。

## 跟弹规则

- 以同一时间戳的所有note-on组成一个目标，不把不同时间的持续音合并进下一目标。
- 只保留该目标中最高音所在的16音组，组内和弦全部亮灯。低组音不发声、不参与过关。
- 单音需要一次新的正确按下；和弦需要所有提示键本步都新按过，并且过关时同时按住。
  可以逐个按下并保持；按错键会正常发出对应音，但不推进。其他额外按键不阻止正确目标过关。
- 目标出现前已按住的键必须先松开再按。连续重复音必须每一步松开重按，不能长按连跳。
- 16键自动映射到当前提示组，指引期间不需要操作pitch_group。已按下音符的松键仍匹配原音高。
- 第6组仅第1～8键有效，第9～16键不发声，也不能代替第8键通过C8。
- 等待期间乐谱进度固定，SD允许继续预读直到FIFO满；不会因为等待时间长而调度超时。
- 按对后直接进入下一组起奏音；休止和仅note-off的时间点自动跳过，不强制原曲节拍或时值。
  因此这是自由速度的按键跟弹，不是按小节、节奏评分或持续时值考核。
- 人的声音由真实压力按下/松开及原有力度控制决定，不由乐谱时值自动代奏。

## 颜色与物理键

颜色表示目标音高组，不表示力度或对错。每一步只显示一种组色。

| 组 | P88S内部索引 | 物理键 | 颜色来源 |
| --- | --- | --- | --- |
| 1 | 0～15 | 1～16 | LED0_RGB，红 |
| 2 | 16～31 | 1～16 | LED1_RGB，绿 |
| 3 | 32～47 | 1～16 | LED2_RGB，蓝 |
| 4 | 48～63 | 1～16 | LED3_RGB，黄 |
| 5 | 64～79 | 1～16 | LED4_RGB，品红 |
| 6 | 80～87 | 1～8 | LED5_RGB，沿用青色配比 |

例如同一时间有索引6、22、25，只亮第7/10灯绿色，按第7/10键即可过关，不要求低组的6。
如果同一时间还有54，则只亮第7灯黄色，只要求按第7键，实际发出索引54。
原七颗静态彩灯及其亮度不变；八路GPIO仍表示有效压力键的长按进度，跟弹实际按键时也可点亮。

## 串口屏开关

沿用115200/8N1及原10字节协议，新增CMD=0x53，P0=0关闭、1开启，P1/P2必须为0。

```text
// 开启跟弹
printh A5 5A 01 00 53 01 00 00 55 0D
// 关闭跟弹，恢复正常自动播放
printh A5 5A 01 00 53 00 00 00 54 0D
```

在main页面新增全局数字控件n8，FPGA回传`main.n8.val=0/1`表示已接受的模式。
n8表示模式偏好，不表示当前一定有曲目或正在等待；n0仍为原来的空闲/加载/播放/错误/手动状态。
模式保持到再次设置或KEY2复位；停止、换曲、自然结束不会关闭这个偏好。复位默认关闭。
开关在空闲时只设置模式，仍需通过现有PN选曲按钮开始；相同模式重复发送不会重启。
播放/加载PN时切换模式会清音并从头加载当前曲目；MB期间设置只保存偏好，不中断MB。
停止、换曲、试听、切乐器、结束或错误都会清除当前目标。

屏幕接入步骤：

1. 在main页面新建全局Number控件`main.n8`，默认0，可隐藏。
2. 新建双态按钮`btGuide`，默认0，两态文字可设为“指引关/指引开”，关闭“发送组件ID”。触摸弹起事件复制
   `screen/tjc_uart/guide_switch_release.txt`。
3. 页面200 ms定时器加入`guide_timer.txt`，用n8同步按钮状态；页面后初始化发送原查询命令。
4. 也可使用两个普通按钮，分别复制`guide_on_release.txt`和`guide_off_release.txt`。

这些文件是可复制事件脚本，仓库没有实际HMI/TFT工程，需要在串口屏IDE添加控件并重新编译下载。
主机工具`tools/send_uart_command.ps1 -Command GuideOn/GuideOff`默认只打印帧；显式指定Port才访问串口。

## 接线与实现

动态灯LED_indicator_dynamic沿用C19、LVCMOS33、3.3 V、DRIVE=8；原静态灯D19。
C19接第一颗DIN，各颗级联并与开发板共地。灯珠供电按实际规格，不能从FPGA数据脚取电。
3.3 V是数据信号电平；灯珠DIN门限若不兼容，应按实际器件处理电平转换。
KEY2保持输出低，释放复位后刷新全黑帧；仅拉低数据线不会立即擦除灯珠锁存颜色。
上传期间动态灯全黑，上传与播放仍需错开。

`piano_score_sequencer`从原事件FIFO收集同时间戳note-on，以3位组号和16位掩码保存最高组目标。
等待时不输出dispatch事件，接收压力合成事件握手及有效按住掩码作判定，FIFO反压保持有效。
`instrument_system`在跟弹PN期间开放原压力通路，声音与HDMI实时瀑布流仍观察实际人的演奏。
灯带另读`guide_keys`目标快照，不再使用实际发声的`video_keys`，所以尚未按键也能提示。
音频仍150 MHz，SD/调度/压力/灯带仍50 MHz，不新增音源、音频ROM或SD文件格式。

灯带仍以88周期扫描锁存快照，发送完整帧。50 MHz下每位63周期，高电平15/45周期，
复位低至少15000周期；每帧384位，约2 ms刷新，目标变化到显示预算约2.8 ms。
停止等变化在下一完整刷新帧清除，不截断正在发送的数据包。

```powershell
python -B tools/check_project.py

```

十一个测试覆盖：88音目标、六色串行协议、最高组和弦、新按/重复音、延迟补读及满FIFO反压、
同时间结束、错误清除、0x53参数/回显、实际顶层UART/SD/ADC/音频/灯带，
并回归板级控制、压力演奏、PN/MB自动播放及视频。
PN/MB正常流程复用视频测试中的原自动播放用例；CRC、格式和空槽异常分别独立运行，
避免四个完整播放器同时例化导致ModelSim Starter容量限速，检查内容保持一致。
日志及输入指纹在`output/key_guide`。仿真不写物理SD卡、不操作开发板，不更新位流。
另用`python -B tools/prepare_follow_synthesis.py`准备隔离工程，
以Gowin执行`output/follow_guide/synthesis/run.tcl`检查综合，不覆盖主工程产物。
完整主工程PnR、时序和实际灯带/按键效果仍需重新编译并上板验证。
