# 马林巴状态存储优化

本次只修改 `src/audio/marimba_synth.v` 的状态保存和读取方式。音源仍为逐样本实时模态合成，没有接入录音播放路径。

## 改动边界

| 状态 | 修改前 | 修改后 |
| --- | --- | --- |
| 192 个模态的相位/幅度 | 32 位和 16 位寄存器数组，动态索引组合读取 | 合并为 48 位同步 RAM；256 项中使用前 192 项 |
| 48 音噪声幅度/LFSR | 两个 16 位寄存器数组，动态索引组合读取 | 合并为 32 位同步 RAM；64 项中使用前 48 项 |
| 力度、待触发和有效标志 | 现有寄存器及事件握手 | 保持原方式 |

频率字、参数 ROM、模态数、动态亮度、噪声种子、相位/幅度位宽、乘法、位截取、舍入、衰减、琴体滤波、限幅和采样率均保持原样。
端口、状态机状态编号和音符接收时机保持一致。
产品端现有 UART 默认值 115200 保持原样；两个按 8 时钟/位发送的加速 UART 集成测试显式覆盖为 9600，避免隐式继承产品默认值而失配。

## 同步读延迟与复位

- NOTE_START 读取当前音的模态 0；MODE_COMMIT/ADVANCE 在切换模态的同一时钟读取下一模态。
- 因而进入 MODE_LOAD 时，相应 RAM 输出已就绪，不增加任何状态或计算周期。
- 噪声状态在 NOTE_START 读取，写回仅发生在 NOISE_COMMIT，两者互斥，避免器件不支持的单口 RAM read-first 模式。
- RAM 内容不挂异步复位；`active_modes`、`active_noise`、`pending` 和状态机处理复位/停止。无效状态不会消费旧数据，新触发从同一初相位和噪声种子开始。
- 同地址读写的结果没有被后续有效计算依赖。

## 音频和时序验证

`tb_marimba_storage.sv` 同时驱动修改前后的音源，每个时钟比较 ready、mix/PCM 有效时刻、音频值、限幅/饱和和超时标志。
测试包含全部 48 音、不同力度、音符范围边界、note-off、重触发、全音复音、随机事件、采样边界同时触发，以及各状态下的复位/停止。
对照已通过 1832 个 PCM 样本，最大完整输出等待 2509 个时钟；原有 48 音测试的混音计算仍为 2496 个时钟，低于每帧 3072 个时钟预算。

完整安卓乐谱还通过现有 `tb_ringtone_synth` 和独立整数模型核对；最终结果和本轮集成测试见 [验证记录](../VERIFICATION.md)。
