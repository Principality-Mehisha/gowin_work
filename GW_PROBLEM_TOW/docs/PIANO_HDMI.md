# 钢琴 SD 播放与 HDMI/DVI 瀑布流

当前主工程已接入原 `dvi_photo` 的 1600×900 / 60 Hz 显示链路。
默认启用 `GW_PROBLEM_TOW.VIDEO_ENABLE=1`，原按键、UART、SD 文件和三种音源继续使用。

## 使用

1. SD 卡根目录放置当前工程的 `sd_card/PIANO.BIN`，使用 FAT16/FAT32。
2. 显示器连接 NEO Dock 的数字视频输出（原 dvi_photo 的 TMDS 管脚）。
3. 下载本工程生成的 `impl/pnr/GW_PROBLEM_TOW.fs`。
4. 在现有串口屏选择第 3 首钢琴曲，或用现有 UART 播放帧选曲参数 `03`。

上电保持键盘画面；钢琴 SD 曲目进入实际播放状态后显示同步落块和亮键。
停止、播放结束、读卡/谱面/合成故障及切换其他曲目后，下一帧清除落块和亮键。
KEY2 复位整个工程。板载 KEY0、KEY1 不参与控制，选曲和单音试听通过 UART 操作。
UART 单音试听不启动瀑布流。输出是 DVI 兼容视频，声音继续从 PT8211 输出，不生成 HDMI 音频包。

## 同步机制

`piano_score_player` 提供实际 `elapsed_ms`、钢琴播放有效标志及 88 位实际接收音符状态。
显示端每次垂直消隐请求一个快照，以请求/确认握手跨越 50 MHz 和 108 MHz 时钟域；整个数据快照在确认期间保持不变。
停止状态的快照强制清除亮键，避免清音寄存器更新的一拍延迟留下旧音。

瀑布流每帧从音频时间重新计算位置，不使用独立递增的动画时间。
音符开始时落块底端位于 y=720 的键盘线，提前三秒的音符位于上方。
首音立即与音频对应，没有原独立演示的三秒启动延迟。已开始的长音仍保留在视野内。
时间换算为 `floor(elapsed_ms * 60 / 1000)`，因此显示按 60 Hz 更新；可见状态存在一帧量级的量化/刷新延迟，实际显示器还可能增加自身延迟。

未来音符来自本工程内置、与 `sd_card/PIANO.BIN` 一致的显示谱面 ROM。
这允许预览未来三秒，而无需修改原有 SD 音频调度或延后音频播放。
亮键由实际送入钢琴合成器的事件控制，曲目归属和播放时间也来自音频系统。

## 资源与模块

`src/video/` 包含视频时钟、原语校准、扫描、场景、键盘映射、谱面、动画引擎、逐行缓存、跨域快照及 TMDS 输出。
原整幅音高位图改为逐行生成两个 88 位掩码，在每行 200 个消隐时钟内完成 64 个音符槽的处理。
这避免了原位图 RAM，使三种音源和显示能同时放入目标器件。
谱面采用 24 位压缩记录（14 位起始帧、3 位音长字典索引、7 位音高）。
几何和音符分配使用分级流水线，在垂直消隐期完成；显示期只读取稳定几何。

视频管脚为数据蓝 J14/H14、绿 J15/H15、红 K17/J17、时钟 G15/G16，沿用原工程约束。
50 MHz 系统时钟生成 540 MHz 串行时钟与 108 MHz 像素时钟。
复位在系统域和像素域分别同步释放，避免把音频域复位直接接入像素域的数据控制路径。

## 替换钢琴曲

显示 ROM 在构建前离线生成，运行时不能自动识别 SD 卡上被外部替换的曲目。
替换 `sd_card/PIANO.BIN` 后运行：

```powershell
python tools/generate_video_score.py
python tools/check_project.py
```

然后重新构建位流，并将同一个 BIN 写入 SD 卡。检查器逐字核对 ROM 与工程内 BIN，防止两者在源码中不同步。
当前压缩格式支持最多 4095 个音符、约 273 秒时间线、8 种不同音长，每音短于约 34 秒；显示同时可见音符不超过 64。
更复杂的谱面需要调整压缩格式或扩展存储，并重新检查资源与时序。

## 验证入口

```powershell
powershell -ExecutionPolicy Bypass -File sim/run_video.ps1 -PythonExe <包含NumPy和Pillow的Python路径>
powershell -ExecutionPolicy Bypass -File sim/run_video_hardware.ps1
```

显示回归检查跨时钟快照、当前曲目全部音符起止时刻、64 槽逐行缓存、同音合并/裁切、完整 144 万像素图像、1800×1000 扫描帧、TMDS，以及实际 SD/UART 播放归属和亮键。
硬件模型入口使用高云官方 PLL/CLKDIV/OSER10 模型检查启动、输出和复位重新锁定。
日志、参考图像及 RTL 预览位于 `output/video_integration/`。原有音频回归仍使用各自入口。
本地仿真和布局布线不能替代显示器与开发板上的最终音画、锁定和信号完整性验证。
