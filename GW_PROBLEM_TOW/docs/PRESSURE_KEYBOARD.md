# 完整压力钢琴

参考工程为`D:\GW_basic_KEYBOARD`。保留现有PN/MB槽位、蓝牙v2和串口屏v1，
不合入参考工程的旧FAT播放分支，也不替换现有马林巴。
本次仅增加压力钢琴；压力键不演奏马林巴。

## 运行方式

- 顶层`PRESSURE_ENABLE=1`默认启用压力输入，上电空闲时可直接演奏钢琴。
- 原`SD_SCORE_ENABLE=0`仍表示上电不自动播放SD，不是关闭SD功能。
- 串口屏选PN/MB时压力事件暂停；SD结束或停止后恢复。
- 串口屏单音试听优先，试听及尾音窗口内暂停压力事件。
- 选马林巴后压力输入暂停，选钢琴后恢复。
- 停止、换曲、试听及切乐器都会清除旧队列和声部；仍按住的已确认按键必须松开再按，不重放旧事件。
- ADC、滤波及校准始终运行，切换模式不会重新标定基线。
- KEY2复位所有状态并重新校准，校准期间松开全部16键。
- 蓝牙仍只上传，上传与SD播放仍由操作者错开；压力演奏不访问SD。

屏幕原命令无需改变。`page0.n0.val=4`现在也包括压力手动演奏及其尾音；
音名文本仍表示串口屏选中的试听音，不表示16键中某一键。
压力队列溢出会锁存错误`0x61`（屏幕十进制97）、清音且暂停演奏。
停止、重新选曲/试听/乐器或KEY2可清除，未松开的键不会自动重触发。
原LED含义保留，不套用参考工程的压力LED布局。
选曲准入已与显示状态解耦，使用已有SD占用寄存器；首次读取目录时可从正在发声的压力钢琴转入SD。

## 接线

新增引脚与参考工程一致，全部为3.3 V接口。不要将5 V输出直接接FPGA。
引脚表为FPGA球位，不是排针脚号。

| 端口 | 球位 |
| --- | --- |
| ADC_DATA[11:0]，从11到0 | E14 C15 B13 A14 B16 A16 A20 A21 E13 C14 C13 A13 |
| S[3:0]，从3到0 | F13 E16 D14 A18 |
| S_EN，低有效 | D17 |
| CLK_500kHz | B15 |
| pitch_group[6:0]，从6到0 | F16 F15 D20 E19 C18 C17 A19 |

分组输入加内部下拉；全0默认第一组，多位置1时最低位置优先。
bit0～bit6分别选基音索引0、16、32、48、64、80、96；
物理键k对应`min(基音+k,87)`，索引0=A0、87=C8。
高音越界夹到C8，同音高多键取最大力度，最后一个持有者松开才发note-off。
切分组不改变已经按下的音高，松键事件仍匹配原来的音。
初测可将bit2置1，得到索引32～47；默认第一组包含低频音，不要以小扬声器听不清低音判断采样失败。

## 采样与力度

与参考工程相同：50 MHz系统时钟、500 kHz ADC时钟、每路30 us、16路一轮480 us。
默认在通道切换后约29.8 us取样；两级输入寄存器不保证12位总线自动一致，
实际ADC的转换边沿、流水线延迟、tCO及模拟通道稳定时间仍需上板确认。
没有虚构ADC输入延时或新增整条ADC路径的false path。
分组开关仅异步输入到第一级同步寄存器设置例外，其余内部逻辑仍按50 MHz检查。
未降低系统、像素或串行时钟目标。

每键启动平均32次样本建立基线，约15.36 ms；按压假定ADC值下降。
Q12.4一阶滤波，下降64码连续3帧确认按下，下降不超过32码连续3帧确认松开。
沿用轻触增强、持续力度合并、32项边沿FIFO和独立同音高持有者跟踪。
力度更新不重启相位/ADSR/琴槌瞬态；每个音频帧增减一个Q0.8单位平滑到目标。
松键后冻结已应用力度，让释放尾音自然完成，后续压力更新不影响该尾音。
钢琴状态RAM在原低83位上增加8位已应用力度；既有调试低位偏移不变。
没有复制新音频ROM，也没有增加一套钢琴音源或限幅器。

## 验证与编译

```powershell
powershell -ExecutionPolicy Bypass -File sim/run_pressure.ps1
```

此入口仅做静态检查、夹具生成和ModelSim仿真，不运行Gowin综合/布局布线。
测试含12位力度全扫描、16键和弦、力度升降、尾音、全部分组组合、
共享C8、反压/溢出、真实顶层ADC/UART/SD/DAC接入、模式切换和KEY2。
另比较新旧力度模式下的常规事件PCM，并验证88音开启实时力度时的计算周期预算。
tb_play_admission主动改变反馈状态，验证其不影响冷启动选曲，同时检查SD占用保护、
已上传槽位切换、同曲不重启、试听抢占和复位。旧代码在此隔离测试中失败，修正后通过。
顶层`PRESSURE_ENABLE=0`可关闭压力功能用于对照；单独的`piano_score_player`默认仍为0以兼容原测试。

最终综合、布局布线和上板由用户执行。现有`.fs`不会由本次仿真更新，
不能当作已包含本功能的新位流；资源占用和物理时序尚待用户编译确认。
