# 马林巴源录音与实时合成参数核查

日期：2026-10-22。音符序号从 1 开始，第 14～23 个音对应工程表内的 MIDI 标签 60～69（C4～A4）。这些是表内标签，不代表当前输出的音高已经正确。

本报告描述修复前的问题版本。其参数、拟合脚本及 RTL 采样已保存在 `sim/marimba_before_fix/`；核查脚本现读取该快照，以便修复后仍可复现原始问题。修复后的测量见 `sim/marimba_corrected_report.json`。

## 结论

当前确实存在参数反演错误。用户指出的中间音区割裂，与第 13→14 个音的模态能量及衰减突变一致。已定位到源采样率被错误解释、错误频带选峰、衰减系数没有转换到输出采样率等问题。没有仅凭频谱指标断言主观听感已经得到修复。

本次新增独立核查脚本、检查报告及原录音/当前合成对照 WAV，未修改合成 RTL、参数 ROM 或 FPGA 位流。

## 1. 源录音是 96 kHz，拟合脚本却固定按 44.1 kHz 解释

`tools/fit_marimba_params.py` 的 `FS = 44100.0` 和 `read_aiff()` 中的 `rate = 44100` 没有解码 AIFF COMM 块中的实际采样率。

核查目标音区所用的全部 12 个源 AIFF（pp/mf/ff，各 4 组）：

- COMM 中的 80 位采样率字节均为 `400fbb80000000000000`，解码结果为 96000 Hz。
- FFmpeg 独立识别 mf/C4B4 文件为 96000 Hz、双声道、24 位 PCM，时长约 43.35 秒。
- 全部文件的 CRC 与原始压缩包内对应成员一致，未发现本地提取后被替换的证据。

因此，原脚本的频率坐标与以秒为单位的分析窗口均不正确。

以第 14 个音为例，原录音实测基频约 263.41 Hz。错误采样率下，这个谱峰落在约 121.01 Hz；原脚本却只在名义 C4 基频的 ±10% 范围内查找，将真正基频排除。当前写入 ROM 的 242.25 Hz，换回正确源采样率约为 527.34 Hz，接近原录音的二次谐波。不能把这种受限频带中找出的最大值当成真实基频。

## 3. 衰减系数直接跨采样率使用

`fit_decay()` 返回源采样序列的逐样本乘数；`write_rom()` 将该乘数直接量化为 Q15，RTL 在每个输出音频采样更新一次。

正确换算关系应为：

```text
alpha_out = alpha_source ** (source_rate / output_rate)
```

源速率为 96000 Hz，输出速率为 50000000/3072 ≈ 16276.041667 Hz。对于相同连续指数包络，直接复制逐样本系数会在无限精度下使时间常数放大约 5.89824 倍。当前实际尾音还受到错误选峰、pp/mf/ff 混合、Q15 量化及每步整数截断影响，不能把这个倍数当成实测听感时长。

为直接比较衰减，将每个音 0～0.1 秒的 RMS 作为起音，0.3～0.5 秒的 RMS 作为尾段：

| 试听序号 | 原录音尾段/起音 dB | 当前 RTL 尾段/起音 dB |
| --- | ---: | ---: |
| 13 | -8.15 | -48.30 |
| 14 | -9.31 | -7.38 |
| 18 | -11.85 | -4.37 |
| 21 | -13.46 | -7.39 |
| 23 | -19.40 | -39.01 |

原录音在第 13→14 个音没有出现与当前输出同量级的衰减断层。这些 RMS 指标反映整段能量变化，不能单独等同于某个模态的指数衰减时间。
