## 四、按照赛题要求，你的音频合成通路应该怎样搭建？

结合你正在使用的高云 FPGA 开发平台，我建议采用下面这条硬件通路作为基础。

交互输入模块

触摸、按键、力度传感器等

演奏控制模块

音符编号、按下/松开、力度、音色选择

多声部振荡器

独立相位累加器、频率控制、波表查找

ADSR 包络与声部混音

音量动态控制、多个音符同时叠加

按固定采样率持续输出数字音频

外部 DAC → 音频输出

这条通路有几个关键点：

1. 音符参数可以预先定义。 你给出的 `case` 语句就是一种常见实现方式。
2. 每个声部都需要独立的发声状态。 至少四个声部同时演奏时，通常需要维护四套独立的相位和包络状态，不能只用一个全局相位累加器反复切换音符，否则容易发生相位状态互相覆盖。
3. ADSR 必须参与实时运算。 按下音符时触发起音和衰减阶段，持续按住时进入延音阶段，松开时进入释放阶段。
4. 混音必须逐样本进行。 每个采样时刻，把各个活跃声部的样本乘以相应包络，再累加、限幅并输出。
5. I2S 持续输出当前合成结果。 不应在按下某个按键后，直接触发一整段预录 PCM 音频的播放。

另外，赛题的基础要求是至少四复音，且控制信号到音频输出的总延迟不超过 10 ms。拓展要求还包括 32 复音或 32 路加法合成分量等指标。因此，设计时最好从一开始就把振荡器、包络、混音和 I2S 输出分成独立模块。

### 1. 你目前实际在做什么？

代码开头就写着：

这已经明确表明音源是录制的钢琴 PCM，并采用 μ-law 编码的 ROM。

进一步看你的实现：


这段代码从 `piano_bank.hex` 读取音频数据，每次读取一个 8 位数据。

再后面，代码通过相邻样本插值、包络增益和输出寄存器，得到最终的 PCM：

这条通路确实是在 FPGA 内部实时执行数字运算，而且输出样本是逐个产生的。但是，逐样本输出不等于逐样本合成。

- Attack（起音）：音量从低电平上升。
- Decay（衰减）：音量下降至延音电平。
- Sustain（延音）：按住音符时维持一定电平。
- Release（释音）：松开音符后逐渐降低至零。

你当前的设计没有完整实现独立的四阶段控制，尤其缺少基于音符释放事件的标准 Release 阶段。

在实时乐器中，这部分需要随着演奏输入动态变化，而不是单纯依赖录音播放到哪里。

建议换成以下四个核心部件：

① 相位累加器

### 核心代码应该是什么样？

下面是一段简化的 DDS 核心示例。它只演示实时振荡器，不是完整的替换文件，波表、复位、包络和接口时序还需要接入你的工程。

```
reg  [31:0] phase;
wire [31:0] phase_step;

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        phase <= 32'd0;
    else if (sample_tick && note_on)
        phase <= phase + phase_step;
    else if (sample_tick && !note_on)
        phase <= 32'd0;
end

// 假设 wave_rom 保存 256 个有符号波形采样点
wire [7:0] wave_addr = phase[31:24];
wire signed [15:0] wave_sample = wave_rom[wave_addr];

// envelope 取值范围为 0~65535
wire signed [31:0] scaled_sample =
    wave_sample * $signed({1'b0, envelope});

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        pcm <= 16'sd0;
    else if (sample_tick)
        pcm <= scaled_sample >>> 16;
end
```

实际编写时还需要注意 Verilog 的乘法位宽、波表的同步读取延迟以及有符号数处理，不能直接把这段示意代码当成最终工程。

相位步进值由下式计算：

\\[ \text{phase\\\_step} =\operatorname{round}\left(\frac{f \cdot 2^{32}}{F_s}\right) \\]

其中 \\(f\\) 是目标音高的频率，\\(F_s\\) 是实际音频采样率。

例如，假设输出采样率为 48 kHz，目标音高为 A4，即 440 Hz，那么相位步进值约为：

\\[ \text{phase\\\_step}\approx39\\,406\\,372 \\]

这与你现有代码里的 `sample_step` 不是同一个概念：旧值控制的是录音片段的读取速度，新值控制的是振荡器每个采样时刻的相位增量。

这张图表示一个完整周期的正弦波。我们可以把它均匀地切分成 256 份，并记录每个位置的幅度。

例如，假设波表采用有符号 16 位数据：

| 地址  | 波表数据（示意） | 含义             |
| --- | -------- | -------------- |
| 0   | 0        | 周期起点           |
| 32  | 11585    | 大约达到正峰值的 70.7% |
| 64  | 16384    | 正峰值            |
| 128 | 0        | 过零点            |
| 192 | -16384   | 负峰值            |
| 255 | 接近 0 的负值 | 接近周期终点         |

这些数值只是示例，实际幅度可以根据设计余量调整。

对应的数学关系是：

\\[ \operatorname{LUT}[k] =\operatorname{round}\left(A\sin\frac{2\pi k}{256}\right) \\]

这里：

- \\(k\\)：波表地址，范围是 0～255。
- \\(A\\)：波表的幅度上限。
- `LUT[k]`：对应相位下的波形幅度。

你也可以准备三角波、矩形波、锯齿波等波表。它们分别对应不同的音色。

关键点：这个波表不包含音符的完整时长。 它只描述一个周期的形状，不论你要产生 110 Hz、440 Hz 还是 1 kHz 的音符，都可以重复使用同一张正弦波表。

# 二、FPGA 如何用同一张波表产生不同音高？

这就是 DDS（直接数字频率合成）的核心。

设音频采样率为 \\(F_s\\)，目标音符频率为 \\(f\\)，那么每输出一个采样点，波形相位就应该前进：

\\[ \Delta \phi = \frac{f}{F_s} \\]

例如，采样率为 48 kHz，要产生 440 Hz 的 A4 音符：

\\[ \Delta \phi=\frac{440}{48000} \approx 0.009167 \\]

也就是说，每输出一个采样点，波形向前走大约 0.9167% 个周期。

但是，如果只用 256 个地址表示相位，地址增量不一定是整数。为了解决这个问题，FPGA 通常采用相位累加器。

## DDS 实时合成的信号流程

音符频率字 `phase_step`

例如 A4 对应的频率控制字

32 位相位累加器

每个采样时刻：phase ← phase + phase_step

取相位高 8 位作为地址

phase[31:24] → 0～255

波表查找 LUT

得到当前采样点的波形幅度

ADSR 包络 × 波形幅度

控制音符的响度变化

PCM 采样值 → 混音 → DAC

例如送入你现有的 PT8211 音频输出模块

32 位相位累加器的完整计算公式是：

\\[ \text{phase}\_{n+1} =\text{phase}\_n+\text{phase\\\_step} \pmod {2^{32}} \\]

相位超过最大值时自然回绕，等价于波形进入下一个周期。

频率控制字为：

\\[ \boxed{ \text{phase\\\_step} =\operatorname{round}\left(\frac{f\\,2^{32}}{F_s}\right) } \\]

假设 \\(F_s=48000\text{ Hz}\\)，A4 的频率为 440 Hz，则：

\\[ \text{phase\\\_step}\approx39\\,406\\,372 \\]

注意：这里的 `phase_step` 不是波表地址增量，而是 32 位相位空间中的增量。取相位高 8 位只是为了访问 256 点波表。

# 三、你提到的“不同波形按权重相加”，也是可行的

你理解的第二部分实际上属于波形混合或音色合成，它与 DDS 的音高控制是两个相互独立的环节。

例如，你希望一个音符既有正弦波的圆润感，又有三角波的柔和泛音，还带有少量矩形波的明亮感，可以采用：

\\[ x[n]=a\\,S[n]+b\\,T[n]+c\\,Q[n] \\]

其中：

- \\(S[n]\\)：当前相位对应的正弦波幅度。
- \\(T[n]\\)：同一相位对应的三角波幅度。
- \\(Q[n]\\)：同一相位对应的矩形波幅度。
- \\(a,b,c\\)：各波形的权重。

这里有一个关键条件：三张波表必须使用同一相位。 这样它们才是在同一个时刻叠加，而不是把三个不同频率的信号随意相加。

## 但是，有个更重要的工程细节

如果你只是把正弦波、三角波、矩形波加权相加，这本身是合理的实时合成方法；不过，它产生的是你设计出来的合成音色，并不自动等于真实钢琴的音色。

真实钢琴声音包含复杂的谐波结构、琴弦振动特征、击弦瞬态以及随时间变化的频谱。简单叠加三种基础波形可以做出可用的电子音色，但听感可能更接近普通合成器。

如果希望音色更像钢琴，可以逐步尝试：

- 使用正弦波与多个谐波成分组合。
- 让不同谐波的权重随时间变化。
- 加入击弦瞬态或轻微的非线性音色处理。
- 使用 ADSR 让音符起音、衰减和释放更自然。

这些都可以通过实时数字逻辑实现，不需要存储完整音符的 PCM 录音。

# 四、你说的“合成逻辑可以提前存储好”，哪些可以提前准备？

这里要区分两类数据。

可以提前准备的数据

- 一个周期的正弦、三角、矩形或自定义波表。
- 88 个琴键对应的 `phase_step` 频率控制字。
- 每种音色的波形权重。
- ADSR 参数，例如攻击时间、衰减时间、延音电平和释放时间。
- 音符序列、节拍和演奏事件。

不应当把它变成的东西

- 提前把 A4 的几秒钟 PCM 全部生成并存储。
- 按下 A4 时直接从 ROM 依次读出这段录音。
- 仅通过加快或减慢录音播放地址来改变音高，再乘一个包络。

对于你正在参加的 FPGA 实时音频合成赛题，第二类做法很可能仍然属于预录音频播放，即使 ROM 中存储的不是原始录音，而是你提前生成的完整音符 PCM。

而第一类做法的核心是：存储的是波形模板和控制参数，实际的每个音频采样值由 FPGA 在运行时生成。

你也可以提前写好一个 `case(note_index)`，为每个音符指定频率控制字。例如：

```
always @(*) begin
    case (note_index)
        7'd48: phase_step = 32'd39406372; // 示例：A4，Fs=48kHz
        // 其他音符对应各自的频率控制字
        default: phase_step = 32'd0;
    endcase
end
```

这里的 A4 编号只是示意，必须与你工程中的音符编号约定保持一致。正式项目建议自动生成完整 88 键的映射，避免手工计算出错。

# 五、ADSR 应该放在哪里？

你关于“波表幅度要留余量，后续再乘 ADSR 增益”的思路是正确的。

一个典型的单音生成流程是：

\\[ \begin{aligned} x[n]&=\operatorname{Waveform}(\phi[n])\\\ y[n]&=x[n]\cdot E[n]\\\ \phi[n+1]&=\phi[n]+\text{phase\\\_step} \end{aligned} \\]

其中 \\(E[n]\\) 是 ADSR 包络系数。

例如，假设波表输出幅度是 0～1 归一化范围，包络也在 0～1 之间变化，那么最终幅度就是两者的乘积。

[a-mc.biz](https://www.a-mc.biz/makemusic/2018/05/30/attack-decay-sustain-release-adsr-explained/?utm_source=chatgpt.com)

1. Attack（起音）：按下琴键后，音量从零逐渐升高。
2. Decay（衰减）：达到峰值后，音量回落到延音电平。
3. Sustain（延音）：按住琴键时，音量保持在设定电平。
4. Release（释音）：松开琴键后，音量逐渐降为零。

需要注意：ADSR 不必以浮点数实现。FPGA 中完全可以使用定点整数，例如用 16 位无符号数表示包络系数，再用整数乘法和移位实现缩放。

此外，你现在的按键消抖模块只输出按下脉冲，后续需要补上按住状态与松开事件，才能正确实现完整的 ADSR。

# 六、最后一步：四个音符怎样同时发声？

当单音模块能够实时产生 PCM 采样值后，多声部混音就比较直观了。

假设四个声部分别演奏 C4、E4、G4、C5，每个声部都有自己的：

- 相位累加器；
- 频率控制字；
- 波形选择或音色参数；
- ADSR 包络；
- 音符按下与松开状态。

每个采样时刻得到四个采样值：

\\[ x_0[n],x_1[n],x_2[n],x_3[n] \\]

然后进行混音：

\\[ y[n]=x_0[n]+x_1[n]+x_2[n]+x_3[n] \\]

混音之后还要做限幅或饱和处理，防止超过 16 位 DAC 的输出范围。

```
wire signed [17:0] mix_sum =
    {{2{sample0[15]}}, sample0} +
    {{2{sample1[15]}}, sample1} +
    {{2{sample2[15]}}, sample2} +
    {{2{sample3[15]}}, sample3};
```

上面这段只演示了如何把四路 16 位有符号采样值扩展后相加；正式工程还需要处理位宽、增益、限幅，以及最终输出到 PT8211 的时序。

## 把整个系统记成一句话

音符决定频率，DDS 决定相位，波表决定波形形状，权重决定音色，ADSR 决定响度随时间的变化，多声部混音把多个音符合在一起。

这套方法不需要为每个音符生成一段完整 PCM 文件，而是可以在每个采样时刻计算出下一个 PCM 值。

对你目前的 Tang Mega 60K 工程，我建议先实现一个最小可运行版本：单张 256 点正弦波表 + 32 位 DDS 相位累加器 + 单音 ADSR + PT8211 输出。确认音高准确、声音连续且没有明显杂音后，再增加多波形混合和四声部。这样比一开始就写完整钢琴合成器更容易定位问题。
