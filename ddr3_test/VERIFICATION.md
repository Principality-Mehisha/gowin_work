# 验证记录

验证日期：2026-10-27。目标：Tang Mega 60K，GW5AT-LV60PG484AC1/I0 / B。

## 实板反馈与修正版 V3

用户烧录原版后观察到：READY 短暂快闪、DONE 灭；1 秒内进入 READY 灭、DONE 快闪。诊断版 V2 随后确认 DONE 每组闪 3 次，即写数据通道超时。

V2 的简化行为模型没有包含真实 MC 的输入流水，漏检了发送端在背压边界的命令/数据失配。使用 Gowin 生成 `.vo` 中的 2148 个原始 MC 实例和厂商 primitive 库后，旧代码复现了同样的 3 号错误：命令 16412、数据 16411、MC 写请求 16554，停止地址 `0x000200D8`。此统计是内部请求，不能当成实板物理写入次数。

V3 仅在两个 ready 同时为高时同拍提交命令与写数据，随后插入两个空闲时钟；读命令仅在 cmd_ready 时提交。保留 V2 报码、DDR3 IP 参数、400 MHz 和整片覆盖范围。2026-10-27 用户再次烧录后反馈“可以了”，记录为用户确认实板运行正常；未另外记录测试轮数、运行时长或冷启动次数。

- 验证六模式、两整轮计数、独立命令/数据背压、错误地址与数据捕获、bit 翻转、地址别名、三类握手超时、校准丢失、读结束标志错误、复位恢复及独立时钟故障指示。

- 诊断版新增仿真逐一校验 1～11 号故障码的重复 LED 脉冲个数、错误编号锁存、时钟丢失和复位检测，全部通过。

## 保留的限制

- **原版和 V2 用户实测失败，V3 用户确认运行正常**。未进行独立仪器采集或长时间稳定性验证。
- 工具保留 PR1014：50 MHz 参考时钟至指定 BPLL 的部分路径使用通用布线。已约束系统时钟使用全局网络，最终内部 setup/hold 检查通过；仍须检查实板冷启动和复位后的校准可靠性。
- SDC 的 sys、memory、UI 时钟域分组沿用 Sipeed 官方 cam_dvi 示例，跨域及 DDR PHY 校准路径依赖厂商实现；这些路径不由普通同步 STA 证明。DDR3 外部采样窗口依赖 IP 训练，时序报告不是 PCB 信号完整性验证。
- 当前 UI 时钟的 STA 余量较小。插入 GAO、改动测试逻辑、换 EDA 版本后都需要重新检查时序。
- 默认构建只用 LED 报告结果；调试寄存器若未接入 RTL GAO，可能被综合优化。
